## 优先处理
1. P1 沙盒广告引擎实际不可用：App.java 仅在主进程初始化 WorkManager；广告库依赖 WorkManager。已有沙盒启动错误日志印证。快捷开关的空值回退只避免闪退，不恢复过滤能力。必须解决进程架构和规则分发，并验证真实规则命中。
2. P1 隐私选项组合失效：WebViewActivity.shouldInterceptRequest 在广告引擎存在时直接 return；后面的第三方请求阻止策略完全被跳过。应先组合策略，再返回结果，并做两开关组合测试。
3. P1 所有网页都被注入 visibilitychange.stopImmediatePropagation：injectPageSettings 无后台播放开关判断。可能阻止网站自己的暂停、节流与状态同步；后台媒体又默认开启，需缩小作用范围并测熄屏。
4. P2 媒体唤醒锁没有超时：BackgroundPlaybackService.acquire() 依赖 stop/页面事件释放。生命周期有清理且真机当前未持锁，但丢失 pause 事件、脚本主动发送 playing 可造成长期保活。应增加播放存活校验与兜底，不可将它写成已确认耗电泄漏。
5. P2 YouTube observer 观察整个 document 子树 class/disabled 变化；250ms 合并只限制扫描，不消除 mutation 回调。活跃视频页可能频繁唤醒；应观察播放器范围，并在隐藏/恢复时管理订阅。pagehide 断开后没有 pageshow 重建，BFCache 恢复也需测试。当前属于广告卡片隐藏/自动跳过，不能宣传视频广告全面拦截。
6. P2 无边框设置入口退化：btnBrowserRestoreControls 为 0 高度、alpha 0，但 Java 将其设为 VISIBLE。自动化 performClick 能成功不代表用户可以触控。需要真实边缘手势与无障碍替代入口验收。
7. P2 脚本兼容与文案不一致：只支持 page-finished 注入，含 @grant（包括 none）、@require、@resource 全部静默退出；缺少匹配域和 manager API，不能当作 Tampermonkey 兼容。
8. P2 测试确定性不足：UtilUnitTests 依赖 xda/orf 等外网网站和固定 favicon 地址；此前曾失败，本次通过。应用逻辑测试应使用本地固定响应，在线测试独立标注。
9. P2 WebView 资源管理需补验：布局同时创建普通/广告两个 WebView，销毁路径主要处理当前 wv 和 popupParents，未使用的布局 WebView 未显式 destroy。需堆分析确认是否残留，不能直接定为已发生泄漏。

## 已有合理防护
- 自动刷新至少 5 秒，pause/destroy 清除 handler；没有在这一路径发现无限后台刷新。
- 页面监控默认关闭，unique periodic work 15 分钟且要求网络；未启用会取消周期任务。
- 媒体服务 START_NOT_STICKY、有停止通知、task removal/destroy 释放逻辑。
- Favicon 4 线程、in-flight 去重、失败冷却；线程池常驻本身不等于 CPU 空转。
- 同沙盒共享数据目录、跨进程配置存储已有实现和测试；仍需登录、进程死亡与冷启动回归。
